# Правила интерфейса

Правила для каждого окна, диалога и уведомления программы. Цель - окно, которое ведёт себя как родное окно
Windows 11 (Fluent). Прочитайте это перед изменением интерфейса; код, который правила проверяет, назван ниже.

## Окна и диалоги

1. У каждого окна, диалога и уведомления есть заголовок в строке заголовка, его можно перетаскивать за неё, в ней
   есть кнопка закрытия (X), Esc закрывает окно (Отмена/Закрыть), Enter нажимает кнопку по умолчанию.
2. Никаких закреплённых, неподвижных и безымянных всплывающих окон. Начальная позиция по умолчанию допустима (по
   центру, для уведомлений - справа внизу), закрепление - нет.
3. Esc и Enter получает только верхнее окно, как в Windows, где клавишу получает активное окно. Удерживаемый Enter
   (автоповтор) диалог не подтверждает.
4. Модальное окно - только когда действие нельзя продолжить без ответа. Уведомления - немодальные всплывающие
   окна с крестиком; они же попадают в журнал событий.
5. Подробности (описание версии, журналы, длинный текст) не раскрываются внутри таблиц и списков: кнопка открывает
   их в отдельном окне.
6. Диалог никогда не выходит за главное окно: `dialog_window` держит каждое окно внутри области содержимого главного
   окна с отступом 12 px (`window_bounds`) - и положение, и наибольший размер, в том числе после уменьшения главного
   окна. Предел размера держит окно с изменяемым размером; окно по размеру содержимого растёт вместе с ним, поэтому
   содержимое обязано умещаться само: текст переносится, длинное уходит в свою `ScrollArea` окна (окно обновлений
   прокручивает историю; таблица компонентов и кнопки остаются на виду). Тест `dialogs_stay_inside_the_main_window`.
7. Колонки таблиц подбирают ширину сами: колонка не у́же самого широкого содержимого (заголовка или ячейки),
   заголовок выровнен как значения колонки (текст слева, числа справа), лишняя ширина остаётся после последней
   колонки, а не между колонками. Только когда окно у́же таблицы, колонка имени ужимается и обрезается с подсказкой
   (`column_widths` в `src/app/updates.rs`, тест `columns_take_the_width_of_their_widest_content`).

## Внешний вид

1. Windows 11 Fluent: скруглённые углы (8 px у окон, 4 px у элементов), Segoe UI Variable / Segoe UI, системный
   акцентный цвет, мягкая тень, без жёстких рамок. Единственное исключение - акцент режима 2 (жёлтые значок, кнопка панели задач и рамки).
2. Три темы: Графит (тёмная, по умолчанию), Сланец (мягкая сине-серая тёмная) и День (светлая), плюс «Как в Windows»
   (День, когда приложения Windows в светлой теме, иначе Графит). Выбор в «Настройки…» - «Общие» - «Тема»
   (параметр `theme` в `Settings.ini`). Смена применяется со следующего кадра, без перезапуска; заголовок окна
   Windows следует теме.
3. Цвета берутся только из `Palette` активной темы в `src/app/theme.rs` (`palette()`); тест
   `colours_come_only_from_the_palette` запрещает цвета-литералы и базовые `Visuals` egui в остальном `src/app`. В
   Дне у выбранной строки ещё и полоса акцента 3 px слева: светлая заливка выбора одна почти не видна.
   Любой цвет текста, включая слабый, имеет контраст не меньше 4.5 (WCAG AA) на фонах темы; слабый текст остаётся
   тусклее обычного (тест `every_palette_meets_wcag_contrast_targets`).
   Активный туннель заметен в списке: его кружок чуть крупнее, а имя написано цветом кружка - зелёным, когда
   подключён, жёлтым, пока подключается, переподключается или не проходит пинг (`name_color` в
   `src/app/list/rows.rs`). У отключённых туннелей, при неизвестном состоянии (нет связи с ядром) и при ошибке текст
   обычный; об ошибке говорят красный кружок и подсказка. Эти два цвета состояний насыщенные (хрома CIELAB не меньше
   45, цветовое отличие CIE76 от серого отключённых не меньше 45) и читаемы с контрастом 4.5 и в выбранной строке
   (тесты `active_status_colours_stand_out_from_idle`, `active_tunnel_name_reads_on_every_row_background`).
   Значки на панели задач и в трее от темы не зависят.
4. DPI: масштаб для каждого монитора; ничего не обрезается при 100-300 %.

## Кнопки и клавиатура

1. Кнопки - справа внизу в порядке Windows: главная (залитая акцентом) первой, затем «Отмена»; окно свойств
   добавляет «Применить» последней («ОК» / «Отмена» / «Применить»). Минимальная ширина около 80 px, в диалоге одна
   кнопка по умолчанию. Порядок задан в одном месте, `button_row` в `src/app/dialog.rs` (тесты
   `property_sheet_buttons_are_ok_cancel_apply`, `button_row_lays_out_in_list_order`).
2. Клавиатура: понятный порядок Tab, видимый фокус, мнемоники Alt в меню, контекстное меню по правому щелчку и по
   Shift+F10 / клавише меню, только через `menu::context_menu` (тест-ограда `context_menus_go_through_the_helper`).
3. Клавиатура строки меню — в одном месте, `MenuNav` в `src/app/menu.rs`: F10 или одиночный Alt (`AltTap`) ставят
   фокус на первое меню, Alt+буква открывает меню, в названии которого перед этой буквой стоит `&` (`&Файл`),
   Влево / Вправо — соседнее меню, Вверх / Вниз и Enter работают внутри, Вправо на пункте с подменю открывает его,
   Влево или Esc в подменю закрывают его, Esc — шаг назад. Подкласс окна глотает `SC_KEYMENU` (кроме Alt+Пробел),
   поэтому F10 и Alt не включают режим системного меню Windows (`swallows_system_key`). Одиночный Alt
   распознаётся по `ModifiersChanged`; на Windows winit шлёт это событие раньше самой клавиши, а egui-winit отдаёт
   Alt как `Key::AltLeft` / `Key::AltRight`, поэтому `AltTap` не считает нажатием собственную клавишу Alt (любая
   другая клавиша или щелчок при нажатом Alt отменяют его). Русские мнемоники переводятся в клавишу по раскладке
   ЙЦУКЕН, поэтому работают в любой раскладке. Горячие клавиши команд (Ctrl+N, Ctrl+I, F1, F5) — из одной таблицы
   `SHORTCUTS`, она же даёт текст справа у пункта меню. Тесты: `menu_mnemonics_are_unique_per_language` (падает на
   повторе буквы во встроенном языке), `shortcuts_map_to_commands`, `menu_bar_keys_walk_like_windows`,
   `arrows_open_and_close_submenus_like_windows`, `window_filter_takes_only_the_keyboard_menu_command`,
   `lone_alt_becomes_f10`, `alt_own_key_events_do_not_cancel_the_tap`.

## Действия, которые рвут VPN

1. Активация строки (двойной щелчок, `Enter`) делает только безопасное: подключает туннель и никогда не отключает.
   Решение — `Primary::activation` в `src/app/list.rs`, тот же `Primary`, что у кнопки карточки, меню строки и трея.
2. Отключение (кнопка карточки, меню строки, трей) сначала спрашивает, с галочкой «Больше не спрашивать». Правило
   одно — `list::asks_first` (окно и трей); ответ — `DialogId` в `hidden_dialogs`, «Настройки… → Снова
   показывать скрытые диалоги» его сбрасывает.
3. Подсказка говорит, что ещё изменит действие, если окно это знает: «Подключить» называет туннели, которые отключит
   ядро (`Primary::connect_hint`). Сами правила — в ядре; окно их только показывает.

## Параметры

1. Параметры — в окне «Настройки» (`src/app/settings_dialog.rs`), а не флажками и полями в меню: меню закрывается от
   потери фокуса, и ошибке ввода в нём негде появиться. В меню — только команды.
2. Окно правит черновик. «Отмена», крестик и Esc его бросают; «ОК» и «Применить» применяют всё разом и только при
   верном вводе: неверный узел пинга (`ping::valid_host`: имя узла или адрес IPv4) показывает ошибку под полем и
   выключает «ОК» и «Применить». Наполовину применённых настроек не бывает.
3. Применённые значения идут прежними путями: `push_options` (агенту — `SetPing`, трей), `Action::Autostart`,
   `Action::ChooseMode` со своим окном подтверждения. Новый параметр добавляется в `Choices` и в эти пути, второй
   реализации у него нет.
4. «Сбросить» сначала спрашивает и сбрасывает только черновик; режим работы и автозапуск остаются как есть.

## Ошибки и текст

1. Ошибки действий уходят в журнал событий (и в `window-errors.log`); строка состояния показывает только ссылку на
   журнал, без текста ошибки. Ссылка держится, пока журнал не откроют: ошибка, пришедшая, пока окно было скрыто в
   трее, видна при следующем показе (`src/app/errors.rs`).
2. Даты всегда `ГГГГ.ММ.ДД`, время `ЧЧ:ММ`, через единый форматтер `src/fmt.rs` (`date`, `date_time`,
   `date_time_sec`). Не форматируйте даты в коде интерфейса.
3. Все видимые пользователю строки - через `src/i18n.rs`, на английском и русском ([CONTRIBUTING.md](../CONTRIBUTING.md)).

## Интерфейс - только из общих помощников

1. Окна создаются только функцией `dialog_window` из `src/app/dialog.rs`; она задаёт строку заголовка, крестик,
   перетаскивание и положение. Ряды кнопок (`dialog_buttons`, `dialog_choice`, `dialog_ok_cancel_apply`) и клавиши (`window_escape`,
   `window_keys`) лежат там же.
2. Охранный тест `windows_follow_the_standard` в `src/app/dialog.rs` падает, если в `src/` создаётся окно egui
   мимо `dialog_window` или в `src/app/` встречаются `.anchor(`, `.movable(false)`, `.title_bar(false)`.
3. Нужен шаблон, которого помощник не умеет: расширьте помощник, не пишите окно «на один раз».
4. Нарисованное painter-ом вместо виджета egui (строки таблицы, графики, точки состояния) обязано вызвать помощник
   доступности `describe` из `src/app/a11y.rs`, иначе экранный диктор видит пустой прямоугольник. Новый вид
   нарисованного элемента - новый вариант `Painted` там же, а не свой вызов `widget_info`.

## Проверка перед отправкой

Пройдите изменение в живом окне (достаточно `awg-ui.exe --demo`):

1. Перетащите за строку заголовка, закройте крестиком и Esc, подтвердите Enter.
2. Пройдите по Tab и посмотрите на фокус.
3. Оба режима работы (режим 2 жёлтый), масштаб Windows 100 % и 150 %.

Напишите в pull request, что вы проверили.
