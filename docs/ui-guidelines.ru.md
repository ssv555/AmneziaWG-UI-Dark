# Правила интерфейса

Правила для каждого окна, диалога и уведомления программы. Цель - окно, которое ведёт себя как родное окно
Windows 11 (Fluent). Прочитайте это перед изменением интерфейса; код, который правила проверяет, назван ниже.

## Окна и диалоги

1. У каждого окна, диалога и уведомления есть заголовок в строке заголовка, его можно перетаскивать за неё, в ней
   есть кнопка закрытия (X), Esc закрывает окно (Отмена/Закрыть), Enter нажимает кнопку по умолчанию.
2. Никаких закреплённых, неподвижных и безымянных всплывающих окон. Начальная позиция по умолчанию допустима (по
   центру, для уведомлений - справа внизу), закрепление - нет.
3. Esc и Enter получает только верхнее окно, как в Windows, где клавишу получает активное окно. Удерживаемый Enter
   (автоповтор) диалог не подтверждает.
4. Модальное окно - только когда действие нельзя продолжить без ответа. Уведомления - немодальные всплывающие
   окна с крестиком; они же попадают в журнал событий.
5. Подробности (описание версии, журналы, длинный текст) не раскрываются внутри таблиц и списков: кнопка открывает
   их в отдельном окне.

## Внешний вид

1. Windows 11 Fluent: скруглённые углы (8 px у окон, 4 px у элементов), Segoe UI Variable / Segoe UI, системный
   акцентный цвет, системная тёмная/светлая тема, мягкая тень, без жёстких рамок. Единственное исключение -
   акцент режима 2 (жёлтые значок, кнопка панели задач и рамки).
2. DPI: масштаб для каждого монитора; ничего не обрезается при 100-300 %.

## Кнопки и клавиатура

1. Кнопки - справа внизу: главная (залитая акцентом) первой, затем «Отмена». Минимальная ширина около 80 px, в
   диалоге одна кнопка по умолчанию.
2. Клавиатура: понятный порядок Tab, видимый фокус, мнемоники Alt в меню, контекстное меню по правому щелчку и по
   Shift+F10 / клавише меню, только через `menu::context_menu` (тест-ограда `context_menus_go_through_the_helper`).

## Ошибки и текст

1. Ошибки действий уходят в журнал событий (и в `window-errors.log`); строка состояния показывает только ссылку на
   журнал, без текста ошибки.
2. Даты всегда `ГГГГ.ММ.ДД`, время `ЧЧ:ММ`, через единый форматтер `src/fmt.rs` (`date`, `date_time`,
   `date_time_sec`). Не форматируйте даты в коде интерфейса.
3. Все видимые пользователю строки - через `src/i18n.rs`, на английском и русском ([CONTRIBUTING.md](../CONTRIBUTING.md)).

## Интерфейс - только из общих помощников

1. Окна создаются только функцией `dialog_window` из `src/app/dialog.rs`; она задаёт строку заголовка, крестик,
   перетаскивание и положение. Ряды кнопок (`dialog_buttons`, `dialog_choice`) и клавиши (`window_escape`,
   `window_keys`) лежат там же.
2. Охранный тест `windows_follow_the_standard` в `src/app/dialog.rs` падает, если в `src/` создаётся окно egui
   мимо `dialog_window` или в `src/app/` встречаются `.anchor(`, `.movable(false)`, `.title_bar(false)`.
3. Нужен шаблон, которого помощник не умеет: расширьте помощник, не пишите окно «на один раз».

## Проверка перед отправкой

Пройдите изменение в живом окне (достаточно `awg-ui.exe --demo`):

1. Перетащите за строку заголовка, закройте крестиком и Esc, подтвердите Enter.
2. Пройдите по Tab и посмотрите на фокус.
3. Оба режима работы (режим 2 жёлтый), масштаб Windows 100 % и 150 %.

Напишите в pull request, что вы проверили.
